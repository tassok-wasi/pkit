# AGENTS.md

## Project

`pkit` is a Go 1.26 CLI for local PKI management: keys, X.509 certificates, CSRs, and CRLs. It uses SQLite at `~/.pkit/pkit.db` and stores the master encryption key in the OS keyring.

- Module: `github.com/tassok-wasi/pkit`
- Entrypoint: `cmd/pkit/main.go`
- Layers: `internal/cli` -> `internal/service` -> `internal/store`; `internal/crypto` and `internal/pki` hold domain logic.
- SQLite driver in use is `modernc.org/sqlite` (`sql.Open("sqlite", ...)`). `mattn/go-sqlite3` is still blank-imported in `internal/cli/init.go` but nothing opens the `sqlite3` driver; do not mix drivers.
- Real CLI runs need an OS keyring; tests mock it, so CLI smoke tests can fail in headless environments.
- `.rules` requires using the codebase-memory-mcp graph for navigation before reading files.

## Commands

```bash
make build                 # tidy, fmt, then build bin/pkit
make test                  # go test -v -race ./...
go test ./...              # faster, no race
go test ./internal/service -run TestName -v
go test ./internal/cli/cert/...
make lint                  # requires golangci-lint to be installed
```

Run `go build ./...` and `go test -race ./...` after changes. Most tests use in-memory SQLite and a mocked keyring; they do not need a real `~/.pkit` database.

## Generated Code

`internal/store/sqlc/*` is generated from `schema.sql` and `query.sql`. Never edit it by hand.

After changing either SQL file:

```bash
cd internal/store && sqlc generate
```

The repo was generated with sqlc v1.31.1. Keep `internal/store/sqlc.yaml` in sync.

## Database and IDs

- IDs are 12-character lowercase hex strings generated by SQLite via `lower(hex(randomblob(6)))`. Do not revert to integer IDs.
- Inserts use `createWithIDRetry` in `internal/service/key.go` for collision retries.
- `query.sql` intentionally orders lists by `rowid`, not `id`, to preserve insertion order.
- Schema changes require bumping `SchemaVersion` in `internal/store/conn.go` and `PRAGMA user_version` in `schema.sql`. `GetConnection` rejects mismatched databases.
- Schema/encryption changes require a fresh database. `pkit init` refuses an existing DB; back up before removing `~/.pkit/pkit.db`.
- Database directory and files are secured to `0700`/`0600`; SQLite uses WAL, `busy_timeout(5000)`, and `synchronous(NORMAL)`. Do not loosen these.

## Encryption Format

Private keys use pkit's own encrypted PEM format, not standard PKCS#8 encryption.

- `Encrypt`/`Decrypt` take an AAD and prepend a `PKIT1` version marker.
- The AAD is derived from the matching public-key PEM.
- `EncryptPrivateKey(priv, publicKeyPEM)` and `DecryptPrivateKey(privPEM, publicKeyPEM)` both need the public PEM.
- Changing this format breaks existing databases; treat it as a schema/format migration.

## PKI Invariants

- `internal/pki/certificate.go` enforces issuance rules: valid cert type, CA `CertSign`, no `CertSign`/`CRLSign` on leaves, issuer `CertSign`/validity, path-length constraints, parent key matching, and child expiry not exceeding issuer expiry.
- `--path-len` is a `*int`: omitted means unconstrained, explicit `0` means leaf-only. Negative values are rejected.
- Leaf default key usage depends on key type: RSA gets `DigitalSignature|KeyEncipherment`; ECDSA/Ed25519 get `DigitalSignature`.
- `internal/crypto/keyusage.go` validates key usage strings and combinations. Unsupported ECDSA P-224 was removed; do not reintroduce SHA-1 signing.
- `VerifyCertificateChain` uses `x509.Verify` plus latest-CRL revocation checks. Do not replace it with signature-only checks.

## CSR Rules

- `csr generate` auto-generates a key from `--type` when `--kid` is omitted.
- `csr sign` verifies the CSR self-signature, requires `PENDING`, checks the CSR public key against the stored key, and only allows `LEAF`/`INTERMEDIATE`.
- `UpdateCSRStatus` updates by CSR `id` and only while `PENDING`. Never update CSRs by `common_name`.

## CRL Rules

- Leave `SignatureAlgorithm` unset in `x509.RevocationList`; Go selects it from the signer key. Setting it from the issuer certificate breaks cross-algorithm hierarchies.
- Empty CRLs are valid and supported.
- CRL names include issuer ID and CRL number; latest CRL is selected by `crl_number`.
- `remove-from-crl` is not accepted for full CRLs; it remains only in the marshal path for legacy display.

## CLI Notes

- `cmd/pkit/main.go` parses arguments before opening the database, so `pkit --help` works uninitialized. Keep that order.
- Help uses `kong.ConfigureHelp(kong.HelpOptions{NoExpandSubcommands: true})`; removing it flattens all subcommands into top-level help.
- `pkit key verify <id>` verifies a stored key pair's private/public match, not a certificate lookup.
- Certificate/key IDs are short strings; format them with `%s`, not `%d`.

## Testing Conventions

- Packages that touch persisted keys or the DB have a `TestMain` calling `keyring.MockInit()` and `crypto.InitMasterKey()`; add one if you introduce such tests.
- CLI/service/store tests share an in-memory database per package. Use unique names, serial numbers, and IDs (for example, suffix with `t.Name()` or a timestamp) to avoid cross-test UNIQUE/FK failures.
- Tests often seed data directly through `testQuerier`; production code should still go through `internal/service`.
- Add focused regression tests for security-sensitive behavior rather than only happy paths.
